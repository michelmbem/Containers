# Keycloak identity and access management

This group contains Keycloak in development mode, PostgreSQL, pgAdmin, and a realm import file. Start with `docker compose up -d`, stop while retaining data with `docker compose stop`, or remove containers with `docker compose down`. Add `-v` to delete the Keycloak, PostgreSQL, and pgAdmin data; add `--rmi all` to remove images as well (`docker compose down --rmi all -v` resets the group).

## Keycloak

Keycloak provides identity, authentication, and access management for applications. It uses PostgreSQL rather than the built-in development database. Open the admin console at `http://127.0.0.1:8181`; the bootstrap development credentials are `admin` / `admin`. The `example` realm is imported at startup from `realm/example-realm.json` when it does not already exist. It defines realm roles `user` and `admin`, users `mike` (`mike@local.org`, password `mike.1`, role `user`) and `danny` (`danny@local.org`, password `danny.1`, role `admin`), plus confidential OpenID Connect clients `inventory` and `shop` with service accounts enabled. Their development client secrets are `inventory-secret` and `shop-secret`.

- [Project and docs](https://www.keycloak.org/documentation) · [Docker image](https://quay.io/repository/keycloak/keycloak) · [GitHub](https://github.com/keycloak/keycloak)
- Isolated example: `docker run -d --name keycloak -p 127.0.0.1:8181:8080 -e KC_BOOTSTRAP_ADMIN_USERNAME=admin -e KC_BOOTSTRAP_ADMIN_PASSWORD=admin -e KC_DB=postgres -e KC_DB_URL=jdbc:postgresql://postgres:5432/keycloak -e KC_DB_USERNAME=keycloak -e KC_DB_PASSWORD='<database-password>' -v keycloak_data:/opt/keycloak/data -v "$PWD/realm:/opt/keycloak/data/import:ro" -v "$PWD/providers:/opt/keycloak/providers:ro" quay.io/keycloak/keycloak:latest start-dev --import-realm`
- Options: `postgres:17` persists the realm, user, and client database in `keycloak_postgres_data`; Keycloak connects over the Compose network as `postgres`. `keycloak_data` at `/opt/keycloak/data` holds Keycloak runtime information, not the realm database. pgAdmin is at `http://127.0.0.1:5051` (default login `admin@local.org` / `admin`); it preloads a `Keycloak PostgreSQL` server definition and uses the local, Git-ignored `./pgadmin/.pgpass` file for the connection password. If `KEYCLOAK_DB_PASSWORD` is changed in `.env`, update that passfile to match. `PGADMIN_REPLACE_SERVERS_ON_STARTUP` keeps the imported server definition aligned on each start. Set `KEYCLOAK_DB_PASSWORD`, `PGADMIN_EMAIL`, and `PGADMIN_PASSWORD` in a local `.env` to override development defaults. The realm import is not applied again if realm `example` already exists. Provider JARs are read from `./providers`; realm JSON files are read from `./realm`. `start-dev` and the documented sample credentials are for local development only.
